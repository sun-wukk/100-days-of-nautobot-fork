# 第 98 天：社区聚焦 - Dwayne Camacho

## 目标

在今天的挑战中，我们将与社区贡献者和多个挑战日的作者 Dwayne Camacho 交谈。我们将讨论他在 100 天 Nautobot 挑战和更广泛的网络自动化社区中的背景和贡献。

## 关于 Dwayne Camacho

Dwayne Camacho 自 2000 年以来就将自己整个成年生活奉献给了美国陆军，在整个服役期间保持着他的通信背景。在他即将完成 26 年军事生涯并希望在管理岗位十多年后重新过渡回技术/工程角色时，他发现 `100 天 Nautobot` 挑战有助于他专注于学习网络自动化。

我们讨论了他即将到来的过渡、学习、"灵光一现"的时刻，以及他对项目新手的建议。让我们开始吧！

## 与 Dwayne 的问答

1. 告诉我们一些关于你的背景，以及你是如何参与 100 天挑战并最终撰写多个挑战日的。

**Dwayne**：我整个成年生活都在美国陆军度过，2000 年入伍。

在加入之前，我对电子和通信工程感兴趣，并在整个陆军生涯中保持了对通信背景的真实。我一直对通信感兴趣，但我的真正热情在于网络。由于我的 26 年职业生涯即将结束，我想回到更具技术性和工程性的道路上，远离管理，这是我十多年来一直在做的。为了为这一转变做准备，我联系了那些离开陆军并目前在技术岗位工作的人以获取建议。其中一位是 DJ Howard，他是该项目的老朋友和贡献者。我问他我应该学什么来为我自己做准备并使我更具市场竞争力。就在那天晚上，DJ 给我发送了 `100 天 Nautobot` 挑战的链接，并建议我将其作为编程的第一步。我开始挑战作为一种让自己专注于学习和探索网络自动化的方式，这是我真正想要进入的领域。

2. 你对 100 天 Nautobot 挑战有什么贡献？

**Dwayne**：我开始是在自己完成挑战的同时做小的语法编辑。这部分来得更自然，我想是出于习惯，因为我部分工作就是"红笔"修改奖励、建议和评估。

随着我进展，我的参与演变为塑造训练的方法和结构。由于训练是我们陆军工作的重要部分，我利用那个优势，努力使内容更容易理解，特别是从像我这样的新用户的角度。

后来 DJ 问我是否想共同撰写一些内容。我记得我很兴奋地说是的！不完全知道自己将陷入什么！ 他问我对哪两个主题感兴趣。我选择了第 31 天，因为我对该主题已经有些熟悉，然后看了第 36 到 39 天。起初看起来令人生畏，但将其视为挑战和绝佳的学习机会。

3. 你在训练和技术信息方面丰富的背景如何有益于你对 100 天挑战的贡献，特别是对新用户？

**Dwayne**：在训练和向新领域人员展示复杂、难消化信息方面有深入经验非常有帮助。

我们不断训练系统、流程和可能完全不熟悉或人们有不同经验水平的概念。我们不期望他们在第一天就掌握一切。这就是为什么"爬、走、跑"方法在通过 `100 天 Nautobot` 时感觉如此熟悉和相关，因为它具有迭代方法。在我看来，打好坚实基础对长期成功至关重要，特别是在学习新技术时。我总是说在深入高级主题之前你应该掌握基础知识。

我可以很容易地理解学习困难和新用户可能不理解的领域。了解如何教学可能是比技术技能更重要的学习部分。这不是关于在 CLI 世界中成为打字最快的人；而是关于理解命令背后的东西：逻辑、流程和概念。这些才是有效训练真正重要的元素。

4. 鉴于你的背景主要是通信和网络工程，你是如何处理 100 天挑战中学习 Django 和 Python 的？

**Dwayne**：我首先通过阅读代码来理解它背后的逻辑，它在做什么，以及为什么。

当我在写第 36 天时（那天我们实际创建一个站点），我最初摸索着，试图通过 Django 层理解它。Nautobot 和 Django ORM 之间的抽象层有帮助，因为我不需要深入学习 Django，只需要知道如何逻辑地与它交互。

理解第 5 天（那是 ORM 的介绍）是我的一个巨大"灵光一现"时刻。它让我意识到，归根结底，这是关于对象以及如何操作它们。我的方法是弄清楚如何编写结合 Django 语言的 Python 代码来创建对象或修改现有对象。一个主要挑战是创建对象之间的关系，例如 Device 到 Vlan。我知道需要什么属性，但我无法正确使用语法来建立连接。

5. 你提到在你工作背景中有"自己想办法"的文化。这种哲学如何影响你处理 100 天挑战学习和贡献的方式？

**Dwayne**：在我的工作环境中，非常强调"自己想办法"的心态。当有人有问题时，这通常是第一个回应。虽然看起来可能很严厉，但它真的鼓励自力更生和主动性。想法是当你自己一人且任务必须完成时，你需要能够依靠自己。这种文化灌输了独立解决问题的自豪感。

这种心态无疑塑造了我处理 `100 天 Nautobot` 挑战的方式。我花了很多时间阅读文档、测试、破坏东西并从错误中学习。但同样重要的是知道何时放下自尊并寻求帮助。归根结底，这不是关于个人成功而是团队和行动的成功。

6. 你如何在学习和编码过程中使用 AI 工具（如 Copilot）？

**Dwayne**：我认为 Copilot，总的来说 AI 工具很棒，但我很少使用。我的目标是让自己理解代码，而不是仅仅让 AI 倾倒。我更喜欢首先尝试使用 `nbshell` 和 API 文档等工具编写代码。我经常首先在 `nbshell` 中测试代码以查看输出或错误，然后再将其放入 Python 脚本中。

当我遇到困难时，比如无法弄清楚为什么我的语法不正确，那就是我会转向 Copilot 的时候。这种先掌握语法和基础知识的方法使我能够使用 AI 来重构和学习，就像一个高级级别的结对程序员，而不是仅仅按原样获取代码。我相信 AI 应该让我们更高效，但不应该完全取代或为我们做工作。

7. 基于你的经验，你对新手学习像 Nautobot 或网络自动化这样的复杂系统有什么建议？

**Dwayne**：专注于"学习如何学习"这个宏观技能。你必须首先在自己脑海中理解它。专注于大块或概念，"大石头"。像语法、特定 API 方法或过滤器这样的更精细细节可以稍后再来。如果你理解一切都是对象以及系统如何抽象查询，具体细节就更容易了。这是关于拥有那些基础理解和构建块。

另一个帮助我的方法是避免我所谓的"按钮学"，这意味着只是教某人按哪个按钮。不要死记硬背步骤，专注于为什么这些步骤很重要。这样，当某些东西坏了或表现不符合预期时，你实际上可以排除故障，而不仅仅是遵循操作指南。

归根结底，编程和自动化是关于解决问题。如果你理解你正在做的背后的逻辑，工具就会变得更容易使用。

8. 你讨论了理解依赖关系的重要性，比如在创建设备之前先创建设备类型。掌握这个概念如何帮助你？

**Dwayne**：理解依赖关系绝对是令人大开眼界的。例如，意识到你需要先创建设备类型然后才能创建设备，这帮助我理解了创建、分配和关联对象及其属性之间的区别。

这个概念至关重要，因为当你正确建模事物时，你的工作变得既可重复又可扩展。这就是真相来源的真正本质。如果我们创建同一对象的多个实例，这对任何人都没有帮助 - 这样做会导致冲突和配置漂移。从一开始就正确设置关系和层次结构使下游的一切更可靠。

9. 通过 Nautobot、Django 和 Python 你对开源有什么看法？

**Dwayne**：开源为供应商锁定和许可问题提供了解决方案。然而，就像其他一切一样，需要平衡。

成本不仅仅是金钱；还有时间和人员的重大成本 - 需要多少时间来培训人员以及他们是否有能力学习。你不能只是把技术抛给人们并期望他们立即学会。

开源有力量推动界限和加速创新，但成功采用它所需的文化和组织转变才是困难的部分。这不仅是技术转型；这是心态的转变。

10. 你最近将在 100 天挑战中学到的东西应用到了工作中解决一个涉及 Nautobot 前缀的真实问题。你能描述一下那个经历以及你从中得到的教训吗？

**Dwayne**：在 Nautobot 升级后，我们最终有了数百个标记为"Cleanup"的前缀。目标是将这些重新分配给基于其分配的租户的正确的、已存在的命名空间，这是一项非常劳动密集型的任务。一个同事试图用一个使用超过 100 行代码的 Nautobot 作业来修复这个问题，向每个前缀发出单独的 API 调用来更新。使用我从挑战中学到的知识和如何与对象及其属性交互的知识，我能够用不到 30 行代码编写一个完成相同操作的 Python 脚本。

从第 65 天，我了解了效率 和程序可扩展性。对于大型企业，性能至关重要，你可以通过仅返回你需要的相关对象/属性（如租户和命名空间）而不是所有内容来使代码更高效。

通过 `100 天 Nautobot`，我意识到这不是关于完成的任务，而是关于利用这些教训解决现实世界的问题。
